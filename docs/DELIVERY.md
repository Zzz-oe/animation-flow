# ScenePilot 交付简要说明

## 项目概述

ScenePilot 是一个面向动画分镜创作的人机协作编辑器。它把“编辑画面 → 提供导演意图 → AI 评审 → 用户选择建议 → 生成隔离候选 → 对比并接受/拒绝/恢复”串成一个可演示闭环。

交付入口：

- 公开源码仓库：<https://github.com/Zzz-oe/animation-flow>
- 本地演示地址：<http://127.0.0.1:5173/>

## 实现方式

- 前端采用 React、TypeScript 和 Vite；舞台使用浏览器原生 Canvas，场景对象以结构化 `SceneLayer` 保存位置、缩放、旋转、层级、显隐和锁定状态。
- 工作区拆分为镜头列表/图层、分镜舞台/时间轴、创作意图/AI 协作三部分。每个镜头独立保存图层、意图、涂鸦和已应用的候选图片引用。
- Provider 层分为 Mock 和 live 两种模式。Mock provider 根据当前图层关系和导演意图生成确定性的结构化评审与候选，保证无密钥也能完成演示。
- live provider 只调用同源服务端 `/api/review` 和 `/api/revision`，密钥保留在服务端环境变量中。真实评审使用 Qwen3.8-Flash，真实候选使用 Qwen-Image；候选先隔离预览，只有用户明确接受后才覆盖舞台视觉版本。
- 评审结果在进入界面前进行运行时 schema 校验。异常、超时或上游返回结构不匹配时，保留原稿并提供切回 Mock 的路径。
- 使用 `localStorage` 保存演示级恢复状态，支持 PNG 和场景 JSON 导出；这不是云端协作存储。

## 人和 AI Agent 的交互设计

重点不是让 AI 直接重做画面，而是让 AI 成为可审阅、可约束的协作者：

1. 用户先编辑画面并填写镜头目标、情绪、风格和不可改变约束，AI 评审使用这些上下文，而不是只看一张图片。
2. AI 输出结构化问题：严重程度、依据位置、目标图层、修改建议和预期效果。用户可以逐条选择或取消建议，也可以补充指令和保护项。
3. 生成结果始终是 candidate revision，与原稿分离。用户可以预览、接受、拒绝或恢复；任何 AI 请求都不能静默覆盖当前作品。
4. 真实 API 失败、无效 JSON 或模型响应不符合 schema 时，界面明确说明原因，原稿保持不变，并可切回 Mock 完成演示。
5. Prompt 由当前镜头、导演意图、结构化图层、涂鸦、已选建议和保护约束共同构造，使评审和生成服务服从动画工作流上下文。

## 个人投入最多的部分

人工总投入按提交者口径约为 7 小时，不包含 Codex 直接生成代码的时间。投入最多的是需求分析、工作流架构、AI 能力边界和人机协作规范的确定；这些决策决定了产品不会退化成“聊天框加一次性出图”。

其余部分按实际工作内容做粗略拆分：

- 约 1.5 小时：检查编辑、评审、候选、接受/拒绝/恢复之间的状态边界，并人工走通关键流程。
- 约 1 小时：核对真实 API 协议、失败响应和费用风险，确定服务端代理与 Mock 保底策略。
- 约 1 小时：响应式布局、可访问性状态、导出和刷新恢复的人工验收。
- 约 1 小时：整理交付说明、失败案例、已知边界和复现步骤。

以上拆分是对约 7 小时人工投入的说明性估计；没有把无法核验的分钟数写成精确事实。更完整的阶段事实和失败记录见 [`docs/DEVELOPMENT_LOG.md`](./DEVELOPMENT_LOG.md) 与 [`docs/WORKLOG.md`](./WORKLOG.md)。
