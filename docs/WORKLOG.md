# 工作沉淀与决策记录

本文件保留跨阶段有效的产品判断、实现经验、失败教训和待解决问题。每次开发结束时，若产生可复用的新认识则追加；短期执行过程写入 `DEVELOPMENT_LOG.md`。

## 当前共识

- 依据 `EVALUATION.md` 开发；每次开发前读取它。
- 题目重点是动画创作工作流中的人机协作，而非复杂 Canvas 功能。
- AI 先评审并提出可解释建议，用户选择后才生成候选修正。
- 当前作品与 AI 候选隔离，必须允许比较、接受、拒绝或恢复。
- Mock 模式应无密钥完整体验；真实模型接入属于加分项，不能让核心 Demo 失效。
- 动画场景上下文、具体约束、Prompt 设计和可评测性是产品区分度来源。
- 交付说明中的工具、Token、时间、测试、失败和模型能力必须如实、有依据。

## 工作流设计依据

使用完整的“意图 → 编辑 → 评审 → 建议决策 → 生成候选 → 对比 → 接受/拒绝/迭代”闭环，避免将产品缩减为聊天框或单次文生图。保留历史和候选是控制权、可解释性及失败恢复的基础。

## 阶段 1 工作区决策

- 默认演示场景采用雨夜车站「雨停之前」的 01 号镜头，构图将角色放在画面左侧、列车和站台形成空间关系，便于后续评审视觉焦点、留白与遮挡。
- 首屏布局固定为：镜头列表/图层 | 分镜舞台/时间轴 | 创作意图/AI 协作。右侧先呈现创作意图，降低用户直接把 AI 当作一键生成器的风险。
- 当前场景采用 Canvas 绘制的原创几何占位，不伪装成真实图像生成结果；正式生成候选时需与当前稿隔离并标注模式。
- 交互中已加入图层显隐和导演意图编辑；拖拽/变换、历史和评审服务留到后续阶段，避免静态工作区扩张成假功能。

## 阶段 2 编辑器决策

- 使用浏览器原生 Canvas 配合结构化 `SceneLayer` 数据，而不是把修改只画进像素。下一阶段 AI 可以同时接收画面快照和对象元数据。
- 对象坐标使用 0–1 归一化值，缩放限制在 45%–220%，使不同画布尺寸和响应式布局共享同一场景状态。
- 拖动过程中实时更新画面，但只在手势结束时写入一次历史快照；属性输入、显隐、锁定、增删和排序各形成一次可撤销操作。
- 背景与雨幕默认锁定，并在 Canvas 命中测试中穿透，防止全画布气氛层遮挡角色和道具选择；仍可从图层列表选择、显隐或解锁。
- localStorage 用于演示级状态恢复，不把它描述为云端保存。重置场景会恢复 5 个默认图层，导演意图单独持久化。
- 阶段 2 继续使用原生 Canvas，没有引入 Konva/Fabric。当前对象数量和交互范围较小，结构化命中/变换已经够用；如后续复杂度显著上升再重新评估。

## 阶段 2 实际测试发现

- 初版命中测试把全画布雨幕作为最上层对象，导致角色无法点击；改为锁定图层不参与画布命中后解决。
- 初版窄屏 CSS 隐藏了工具栏第二个按钮，恰好使重做不可见；保留原响应式规则并在阶段 2 样式中显式恢复重做按钮。
- 浏览器实测：角色从 X=36%、Y=64% 拖至 X=49%、Y=51%；缩放从 100% 到上限 220%；两次撤销按顺序恢复缩放与位置，键盘重做重新应用移动。
- 新增旅行箱使图层数从 5 变为 6，删除恢复为 5，撤销删除重新出现；角色 X 改为 42% 后刷新同一地址仍为 42%，验证了 localStorage 恢复。测试结束后已重置默认场景。

## 阶段 3 评审闭环决策

- 评审层通过 `ReviewProvider` 接口隔离。Mock 与未来 live provider 返回同一套经过运行时校验的结构，不让视图层信任任意模型 JSON。
- Mock 不是固定演示文案：它读取结构化场景中的显隐、位置、尺度、旋转和对象关系，输出对应问题、证据、修改建议、预期效果、目标图层和可选画布区域。
- 评审请求同时携带 Canvas 快照与结构化对象。当前 Mock 主要使用结构化对象保证稳定可复现；保留快照字段供真实多模态 provider 使用。
- 评审结果保存生成时的场景指纹。用户继续编辑不会被阻止或丢失旧结论，但旧结论会明确标记为过期，重新评审前不得被误认为当前判断。
- finding 选择会同步场景图层，并显示画布区域蒙层；这为阶段 4 的“选择建议后生成候选”提供可复用的目标绑定。
- 特殊意图标记 `[模拟错误]` 只用于可控地触发 Mock 失败测试，错误态声明原稿不受影响，并提供重试/检查意图路径；正式演示文案中不暴露该测试入口。

## 阶段 3 实际测试发现

- 标准 5 图层场景得到 88 分和一条低风险精修建议；隐藏列车后旧报告立即显示“画面已改变”，重新评审得到 73 分和“最后一班车的视觉信息缺失”高优先级建议。
- 点击列车问题卡片后，舞台状态同步为“已选择：末班列车”，画布出现对应 `AI NOTE` 区域，证明建议可定位到结构化对象而非只有聊天文字。
- 使用 `[模拟错误]` 触发 provider 失败后，界面显示错误与恢复路径；移除测试标记、恢复列车并重试后回到 88 分标准结果。浏览器控制台没有 error/warn。
- 首次阶段构建暴露 `unknown` 数字校验没有形成 TypeScript 类型谓词；将 `isNumber` 声明为类型谓词后，运行时校验语义不变且严格构建通过。
- 一次浏览器测试使用过宽文本定位器导致测试工具超时；AX 状态随后确认卡片点击其实已经生效，未重复点击，避免误改状态。后续对卡片使用角色或唯一标题定位。

## 阶段 4 建议确认与候选修正决策

- Candidate revision 使用独立的 `baseLayers` 与 `layers` 快照，生成过程只读当前稿；只有用户点击“接受并应用”才调用编辑器的 `commit`，避免 AI 静默覆盖。
- 评审 finding 默认勾选是为了让标准演示少一步，但每条仍可取消；补充指令变化会清除旧候选，防止用户误把旧 Prompt 当作新结果。
- 原稿/候选切换只改变 Canvas 展示，不写入编辑状态；候选预览期间禁用画布拖动，接受后恢复正常编辑。
- 接受候选保存最近一次接受前的快照，恢复动作再次进入撤销历史和协作历史；拒绝只丢弃候选，不改场景。
- 2026-10-01 浏览器回归：标准评审 88 分/1 条建议；生成显示 `CANDIDATE` 和“尚未应用”；原稿/候选切换可用；接受后历史出现“接受候选”和“恢复接受前版本”，恢复后场景回到接受前版本；控制台 error/warn 为 0。

## 阶段 5 真实 Provider 边界（进行中）

- `src/live.ts` 只允许调用同源 `/api/review` 与 `/api/revision`，不在前端读取或保存 API Key；Provider 返回仍经过评审 schema 校验，候选要求 `provider/live/layers/changes` 基本结构完整。
- UI 通过 AI 协作面板切换 Mock/真实 API；切换使用事件同步到 App provider 选择，不改变现有 Mock 默认路径。
- 2026-10-01 浏览器验证：真实模式提示“同源服务端代理 · 浏览器不保存密钥”；当前无后端时收到 HTTP 404，显示“服务端返回 HTTP 404；原稿未被修改”，恢复路径可见。该事实证明降级，不证明真实模型已接通。
- 阶段 5 尚未完成：需要新增安全服务端代理、环境变量说明和真实模型回归；在此之前不把真实模式描述为可运行能力。

## 阶段 5 服务端代理进展

- 新增根目录 `server.mjs`，使用 Node 内置 `http` 和 `fetch`，启动 `npm run api` 后监听 `127.0.0.1:8787`；Vite 开发服务器将 `/api` 代理到该端口。
- 代理只读取服务端 `.env.local`，请求上游 Responses API，要求模型返回 JSON object，并将上游错误转换为 JSON 错误；浏览器仍不会接触密钥。
- 当前只实现真实评审 `/api/review`；真实图像生成 `/api/revision` 尚未实现，避免把文本评审结果伪装成图像编辑能力。
